### Option A: metadata only (low risk)

1. Root `package.json`: add `"name": "paypilotlabs-helpdesk"`.
2. `desk/package.json` name → `paypilotlabs-helpdesk-ui`.
3. `pyproject.toml` `[project.urls]` and description → PayPilotLabs (B7). `[project] name` stays `helpdesk`.

Files touched: `package.json`, `desk/package.json`, `pyproject.toml`. App stays `helpdesk`; routes, imports, assets, Docker and other repos unchanged.

### Option B: full app rename to `paypilotlabs_helpdesk` (high risk)

1. `git mv helpdesk paypilotlabs_helpdesk` (418 tracked files move); `[project] name`, `hooks.app_name` → `paypilotlabs_helpdesk`.
2. Rewrite every `helpdesk.` import and dotted path: 168 files (106 .py imports, `hooks.py` doc_events/scheduler/overrides/`has_permission`, `patches.txt`, doctype JSON, frontend `createResource` URLs `helpdesk.api.*`).
3. Every `/assets/helpdesk/` path (10 files), `desk/vite.config.js` outDir, `pyproject.toml [tool.bench.assets]`, `www/helpdesk/` page.
4. `docker/docker-compose.yml` `--install-app`, `.github/scripts/check_independence.py` `PACKAGE`, CI `compileall helpdesk`, `crowdin.yml`, `MANIFEST.in`, Playwright config.
5. Existing sites cannot upgrade in place: bench sees a new app. Each needs a data migration (`Installed Application`, `Module Def.app_name`, patch log) or a fresh install.
6. Every upstream merge from frappe/helpdesk becomes a large manual conflict.
7. Keep routes at `/helpdesk`.

### Recommendation

**Option A.** Users never see the app name `helpdesk`; they see "PayPilotLabs Helpdesk" in titles, the PWA and the apps screen, which is already done. Option B is a day of edits, breaks upgrades and upstream merges, and changes nothing a customer sees. Same choice as CRM.
